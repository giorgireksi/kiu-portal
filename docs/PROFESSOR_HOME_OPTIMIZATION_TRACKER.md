## Working Findings

1. `index.html?view=professor#home` is not a separate standalone page. It is a shared shell route with professor-specific home data and widgets.
2. The main lag risk is still cumulative startup cost from the shared shell, not just professor-only code.
3. Known heavy paths remain: `updateTransparency()`, the background canvas loop, `observeLegacyVisualTree()`, shell-wide `syncAll()`, and large CSS/JS parse cost.
4. Professor home also inherits dashboard-canvas rendering, faculty/role picker enhancement, and route-wide observer overhead.
5. This batch removed an unreachable legacy home renderer and stopped eagerly creating the large luxury studio modal during shell startup.
6. Visible professor-home shell copy is now clean in the shared startup path, including studio copy, footer copy, role/faculty labels, and widget-facing text.
7. The remaining shared-shell cost is now mostly true runtime work: background animation, transparency refresh on real state changes, and full dashboard re-rendering after explicit navigation or editor actions.
